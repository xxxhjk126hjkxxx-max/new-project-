# دفتر الحضور المحلي بالـ QR — IUA

المشروع تطبيقان منفصلان، كل منهما ملف HTML واحد مستقل تماماً (CSS ومكتبات QR والمنطق كلها مضمّنة داخله) ويعمل بلا إنترنت وبلا خادم:

| الملف | لمن | الوظيفة |
| --- | --- | --- |
| `leader.html` | الليدر | إدارة الطلاب والمحاضرات، مسح رموز QR بالكاميرا، والتقارير |
| `student.html` | الطلاب | إدخال الكود النصي وتوليد رمز QR للحضور |

الليدر ينشئ كوداً نصياً لكل طالب. الطالب يدخله في ملفه لتوليد رمز QR على هاتفه. عند المسح يطابق هاتف الليدر الكود مع الطالب في قاعدة بياناته المحلية، من دون رفع صور أو إرسال سجلات إلى خادم.

## الاستخدام

1. **على هاتف الليدر:** افتح `leader.html` في متصفح حديث. لتفعيل الكاميرا يلزم عنوان **HTTPS بشهادة يثق بها الهاتف**، أو `localhost` إذا كان الخادم على الجهاز نفسه. عنوان الشبكة المحلية بصيغة `http://192.168...` لا يكفي للكاميرا. يمكن أيضاً تشغيل الخادم المدمج (`python app.py`) وفتح `/` من الهاتف عبر HTTPS.
2. **على هاتف الطالب:** انقل ملف `student.html` إلى الهاتف (واتساب، USB، بلوتوث…) وافتحه في متصفح يشغّل JavaScript؛ معاينة المرفقات أو مدير الملفات قد لا تشغّل الصفحة التفاعلية. لا يحتاج الطالب إلى رابط خاص أو إلى إنشاء حساب.
3. من **الطلاب** في ملف الليدر أضف الطالب ثم اختر **كود الطالب**. انسخ الكود النصي أو أعطه للطالب مباشرة.
4. في ملف الطالب يُدخل الطالب الكود ويضغط **توليد رمز QR**.
5. أنشئ محاضرة، واخترها في **مسح الحضور**، ثم وجّه كاميرا هاتف الليدر إلى رمز الطالب. يوجد خيار قراءة صورة رمز كبديل عند تعذّر تشغيل الكاميرا.
6. يسجّل التطبيق الوقت محلياً ولا يسجّل الطالب مرتين للمحاضرة نفسها. يمكن مراجعة الحاضرين والغائبين وتنزيل تقرير CSV.

## أين تُحفظ البيانات؟

| البيانات | مكان الحفظ |
| --- | --- |
| الطلاب وأكوادهم والمحاضرات وسجلات الحضور | قاعدة **IndexedDB** على هاتف الليدر، في نفس المتصفح وعنوان التطبيق. |
| كود الطالب بعد توليد الرمز | مساحة المتصفح المحلية على هاتف الطالب إذا سمح بها المتصفح. يمكن مسحه من صفحة الطالب؛ الرمز يعاد توليده من الكود ولا يُرفع إلى الخادم. |
| ملف CSV | يُنشأ في المتصفح ويُنزّل إلى الجهاز. |

لا توجد مزامنة تلقائية بين الهواتف. لا تعتمد على التصفح الخاص، ولا تمسح بيانات التطبيق؛ امسح رمز الطالب من هاتفه فقط عند الحاجة. صدّر التقارير قبل تغيير الجهاز أو المتصفح. الكود ثابت لهذا الطالب: لا تشاركه مع طلاب آخرين، لأن نسخة منه أو من رمز QR تكفي لتقديمه مرة أخرى؛ لا يتحقق التطبيق من هوية حامل الرمز.

## إعادة البناء بعد تعديل المصادر

الملفان في الجذر ناتجان عن المصادر في `offline_assets/` (وقالب الطالب في `templates/offline_student.html`). بعد تعديل أي مصدر أعد توليدهما بـ:

```bash
python build_single_files.py
```

ثم أعد نشر `leader.html` و`student.html`. لاختبار البناء والمسارات: `python -m unittest discover -s tests -v`.

## التشغيل عبر الخادم (اختياري)

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

يقدّم الخادم ملف الليدر في `/` وملف الطالب في `/student` (و`/student-offline.html` كاسم بديل). لتجربة سريعة على الكمبيوتر: افتح `http://127.0.0.1:5000`. في معاينة Arena يُفضّل فتح التطبيق في تبويب مستقل عند استخدام الكاميرا، ثم منح إذن الكاميرا.

## النسخة السابقة

ما زالت نسخة Flask/SQLite السابقة متاحة عبر `/login` لمن يستخدم بياناتها. قواعد البيانات مستقلة؛ لا تُنقل سجلاتها تلقائياً إلى النسخة المحلية. لا تنشر النسخة السابقة ببيانات الدخول التجريبية: إذا نشرتها فاضبط `ADMIN_USERNAME` و`ADMIN_PASSWORD` و`SECRET_KEY` و`COOKIE_SECURE=true`، واستخدم مسار `DATABASE_PATH` على قرص دائم.
